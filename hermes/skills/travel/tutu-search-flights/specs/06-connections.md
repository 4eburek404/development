# S5 — пересадочный маршрут сохраняет все сегменты

## Дано

Используется записанный ответ `fixtures/avia/connections.json` с перелётом,
содержащим несколько сегментов и self-transfer признаки.

## Когда

Продукт обрабатывает предложение.

## Тогда

- сохраняется структура legs и все сегменты в исходном порядке;
- для каждого сегмента сохраняются перевозчик, номер рейса, аэропорты,
  timezone-aware времена и длительность;
- сегменты остаются внутри исходных `legs[].segments[]`, без добавления
  производных верхнеуровневых полей от продукта;
- неизвестные модели поля на уровне предложения вызывают явную ошибку
  согласно S9; продукт не добавляет `carrier` или `flight_number`;
- маршрут предложения не сворачивается в один выдуманный прямой рейс;
- признаки `has_self_transfer`, `is_multi_pnr` и пояснение источника
  сохраняются, когда они присутствуют.

## Исполнение

Проверка выполняется на записанном raw MCP response без сети:
[tests/test_connections.py](../tests/test_connections.py) — node ID:
`tests/test_connections.py::test_connection_offer_preserves_segments_and_transfer_evidence`.

Проверяются оба предложения и все сегменты записанного ответа.
Неизвестные поля отклоняются до успешного результата; этот отказ на разных
уровнях проверяет S9. Raw fixture не меняется.
