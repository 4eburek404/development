# Поиск авиабилетов Tutu

Перед первым запуском выбери уже установленный Python с зависимостями этого
проекта и задай переменную `PYTHON`. Настройка окружения описана в
[README.md](README.md): на этом Mac используется
`/Users/home/.venvs/hermes-backup/bin/python`; в другом Hermes-окружении укажи
`PYTHON` на его готовый интерпретатор. Зависимости устанавливаются в выбранное
окружение по README, а не при каждом поиске.

Для живого поиска из каталога этого skill передай один JSON-объект с аргументами
`search_avia`:

```sh
"$PYTHON" tutu_search_flights.py '{"origin":"Москва","destination":"Сочи","departure_date":"2026-11-15"}'
```

Это пример формы запроса, а не дата или маршрут по умолчанию: подставь значения
из запроса пользователя. JSON передаётся одним позиционным аргументом, без
JSON-RPC envelope и без вложенного ключа `arguments`.

## Вход поиска

Для обычного поиска укажи `origin`, `destination` и `departure_date`. Если маршрут
или дата неизвестны, уточни их у пользователя. Места передаются строками: название
города (`"Москва"`), аэропорта (`"Шереметьево"`) или IATA-код (`"SVO"`). Для поиска
по всем аэропортам города используй название города. IATA-код не гарантирует
одинаковое разрешение всех мест сервером; не делай вывод об airport-ограничении
только по входу. Даты — строки `YYYY-MM-DD`.

Необязательные параметры (значения по умолчанию задаёт сервер):

| Параметр | Тип, смысл и значение по умолчанию |
|---|---|
| `return_date` | Строка `YYYY-MM-DD`: дата обратного вылета. Без неё поиск в одну сторону. |
| `adults` | Целое 1–9, пассажиры от 12 лет; по умолчанию 1. |
| `children` | Целое 0–9, дети 2–11 лет; по умолчанию 0. |
| `infants` | Целое 0–9, дети до 2 лет; по умолчанию 0. |
| `service_class` | Строка: `Y` — эконом, `S` — премиум-эконом, `C` — бизнес, `F` — первый; по умолчанию `Y`. |
| `direct_only` | JSON boolean: `true` для рейсов без пересадок в каждом направлении; по умолчанию `false`. |
| `price_max` | Неотрицательное число: верхняя граница цены предложения в рублях за всю группу; по умолчанию без ограничения. |
| `carriers` | Массив строк с названиями перевозчиков из источника; по умолчанию без фильтра. Не угадывай написание названий. |
| `flight_numbers` | Массив строк, например `["SU-6176"]`; совпадение с любым сегментом сохраняет весь маршрут. По умолчанию без фильтра. |
| `sort` | `price_asc` (по умолчанию), `price_desc`, `duration_asc` или `departure_asc`. |
| `page` | Целое 1–10; по умолчанию 1. |
| `page_size` | Целое 1–30; по умолчанию 10. |
| `view` | `compact` (по умолчанию) или `full`; в записанных авиаответах `full` не добавляет полей. |

Для поиска туда-обратно на двух взрослых и ребёнка передай, например:

```sh
"$PYTHON" tutu_search_flights.py '{"origin":"Москва","destination":"Сочи","departure_date":"2026-11-15","return_date":"2026-11-22","adults":2,"children":1,"infants":0}'
```

Используй `origin`/`destination`; `from_city`/`to_city` — устаревшие алиасы.
Не добавляй неизвестные параметры. Основание типов, диапазонов и defaults —
записанная схема `search_avia.inputSchema` в
[fixtures/meta/tools-list.json](fixtures/meta/tools-list.json) от 24.09.2026;
это снимок, а не гарантия неизменности живого API. CLI валидирует аргументы типизированной моделью до сетевого вызова; Tutu MCP
дополнительно проверяет их на сервере. Неверный JSON, поля или значения дают
ошибку ввода. Числовые даты не принимаются и не преобразуются из Unix timestamps.
В ответе строки вместо чисел или boolean также отклоняются, а не исправляются.
Неизвестные поля успешного ответа вызывают явную ошибку,
пока модели структуры Tutu не обновлены.

## Выполнение и интерпретация результата

Скрипт подключается к `https://mcp.tutu.ru/mcp` через MCP Python SDK и вызывает
`search_avia`. Не используй native Hermes Tutu MCP tool, `probe.py`, HTTP/curl или
другой transport как production-путь.

Не меняй запрошенные маршрут, даты или состав пассажиров без необходимости.

Для предложения с несколькими сегментами или для round-trip используй `legs` и
`legs[].segments`; не представляй такое предложение как один прямой рейс.

Результат — исходный JSON Tutu: `offers` и `meta`, без собственной проекции.
Цены и условия находятся в `offers[].variants[].price` и `.conditions`, основа
цены и состав группы — в `meta.pricing`. Номер каждого рейса —
`offers[].legs[].segments[].voyage_no`. Не ищи производные поля `fares`,
`pricing_basis` или `flight_number`. Используй исходные названия полей.
`meta.has_more=true` означает, что текущая страница не является полной выдачей.

Если `offers` пуст:
- перед выводом проверь `meta.upstream_note`, `meta.total_matched_exact` и
  исходные счётчики `meta.post_filter_dropped_over_cap`,
  `meta.post_filter_dropped_not_direct`, `meta.post_filter_dropped_wrong_carrier`,
  `meta.post_filter_dropped_wrong_flight_number`, `meta.post_filter_dropped_wrong_airport`;
- не утверждай «рейсов нет», если источник дал объяснение, фильтр отбросил
  предложения или полнота совпадений не подтверждена.

Сообщай только предложения, цены, тарифы и условия, которые присутствуют в результате
поиска. Не додумывай неизвестные значения и не выполняй альтернативные поиски без причины.
